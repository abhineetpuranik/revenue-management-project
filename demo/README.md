# Demo backup and restore

## What's in this folder

| File | Purpose |
|---|---|
| `dump_demo.py` | Creates compressed mysqldumps of both databases |
| `restore_demo.py` | Restores both databases from the dumps |
| `revenue_management.sql.gz` | **gitignored** — ~50–80 MB compressed |
| `revenue_management_gt.sql.gz` | **gitignored** — small |

## "Working demo in 5 minutes"

If you are joining a demo session with MySQL already installed and configured:

```bash
# 1. Clone the repo and install dependencies (skip if done)
git clone <repo-url>
cd "Revenue Management"
cd data-pipeline && python -m venv venv
# Windows: venv\Scripts\Activate.ps1   macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env   # fill in DB_USER and DB_PASSWORD
cd ..

# 2. Create the empty schema
mysql -u root -p < database/schema.sql

# 3. Download the dumps from shared storage (see link below) and place in demo/
#    Then restore:
python demo/restore_demo.py

# 4. Start the backend
cd backend
copy .env.example .env   # fill in DB credentials
python app.py            # -> http://localhost:5000/api/health

# 5. Start the frontend
cd frontend
npm install
npx ng serve             # -> http://localhost:4200
```

Total time: ~3 minutes if MySQL is already installed.

## Which model artifacts do you need?

The following files are committed to the repo and do **not** need to be downloaded:

- `data-pipeline/models/artifacts/production_model.joblib` (745 KB)
- `data-pipeline/models/artifacts/metadata.json` (< 1 KB)
- `data-pipeline/data/elasticity/product_elasticity.csv`
- `data-pipeline/data/segmentation/customer_segments.csv`
- `data-pipeline/data/segmentation/segment_summary.csv`
- `data-pipeline/data/pricing/pricing_candidates.csv`

Only the raw CSVs (`data/raw/`) and cleaned CSVs (`data/cleaned/`) are gitignored and are regenerated by the pipeline.  After restoring the database dumps you do **not** need to rerun the pipeline.
