# Demo Script — AI-Powered Demand Forecasting and Dynamic Pricing

**Duration:** ~10 minutes  
**Audience:** assessors / examiners  
**Setup:** backend running on `localhost:5000`, Angular dev server on `localhost:4200`, browser open

---

## Before you start (2 minutes before assessors arrive)

1. `cd backend && python app.py` — confirm `{"status":"ok"}` at `http://localhost:5000/api/health`
2. `cd frontend && npx ng serve` — wait for "Application bundle generation complete"
3. Open `http://localhost:4200` in Chrome/Firefox
4. Have `docs/results.md` open in a second tab as a numbers reference

---

## Fallback procedures

| Problem | Fallback |
|---|---|
| Backend not starting | Run `python demo/restore_demo.py` then retry |
| Database empty | Run `python demo/restore_demo.py` |
| LLM unavailable | Explanation panel shows "unavailable" — this is expected and worth explaining |
| Frontend build fails | Use `ng build` output already in `dist/frontend`; serve with any static server |

## 5 — Key results summary (1 minute)

> "Across all 50 products the expected weekly revenue uplift is +7.9%. We validated this against the true elasticities we embedded in the dataset — 48 of 50 pricing decisions match the direction you would predict from the true value. The two exceptions are products whose current price already breaks the margin floor, so the model raises to satisfy the constraint even though the true signal would say 'cut'."

## Things to mention if asked

- **Why synthetic data?** We needed controlled price variation and known ground truth. Public datasets like M5 don't have per-product elasticities we can validate against.
- **Why not deep learning?** The dataset is ~7 700 weekly rows. XGBoost outperforms LSTM on tabular data at this scale and is far more explainable.
- **Why can the LLM only explain?** To prevent hallucination. The guardrail checks every number in the output against the input payload. If a new number appears, it falls back to a template.
