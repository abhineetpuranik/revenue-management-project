## 1. Purpose and method

Phase 13 measures the system; it does not change it. The central claim under
test is that the models recover the known structure baked into the synthetic
dataset (`true_elasticity`, `true_segment`). The evaluation layer consists of
six read-only scripts under `/evaluation/`, orchestrated by
`run_evaluation.py`. Each script:

- reads only from the application database (`SELECT` only via
  `etl.db_connection.get_engine`) or the separate ground-truth database
  (`get_gt_engine`);
- never re-fits a model on the test window and never writes a model artifact,
  pipeline CSV, or database row;
- uses `EVAL_RANDOM_SEED = 42` (defined in `evaluation/utils.py`);
- writes machine-readable outputs (JSON/CSV) and figures (PNG) to
  `evaluation/results/`.

Where a data source is unavailable, the script skips the dependent step
gracefully and writes a result file that records `null`/`SKIP` plus the reason,
so that no number is ever fabricated.

## 10. Limitations and threats to validity

1. **Run-environment data gaps (KI-10).** The Phase 13 run could not reach the
   application or ground-truth databases (no `data-pipeline/.env` credentials)
   and could not load the XGBoost native library (missing `libomp.dylib`).
   Therefore all DB- and XGBoost-dependent metrics are `null`/`SKIP` in
   `evaluation/results/` and are marked `[PENDING]` above. Re-running
   `python evaluation/run_evaluation.py` in an environment with DB credentials
   and a working XGBoost installation will populate them; the scripts are
   correct and write the expected files on a full run (confirmed by the
   FEAT-001 implementation).
2. **Segmentation metrics were computed on stored RFM, not live RFM.** Because
   the DB was down, RFM was loaded from the committed Phase 6
   `customer_segments.csv` rather than recomputed from the `sales` table. The
   k-search, RFM profile, and stability numbers are real, but a live-DB
   re-run should confirm they match a freshly computed RFM.
3. **Ground-truth comparison not yet available.** ARI/NMI/purity
   (segmentation), MAE/RMSE/Pearson/Spearman (elasticity), and the
   evaluation-only true-elasticity-vs-price-direction correlation could not be
   computed because `revenue_management_gt` was unreachable. These are the
   core "model recovers known structure" checks and remain the most important
   pending results.
4. **LLM live checks not run.** Numeric consistency and latency require
   `--with-llm` and an `LLM_API_KEY` (off by default to avoid paid calls). The
   guardrail *logic* is validated by unit tests and the prompt-construction
   check, but end-to-end LLM output was not exercised in this run.
5. **Single run, no multi-seed pipeline re-fit.** Per the plan, the optional
   full-pipeline multi-seed stability run was skipped (a from-scratch run
   exceeds the ~10-minute threshold). Segmentation stability was instead
   measured by re-running K-Means only on the RFM data across five seeds
   (required, not optional), which returned ARI = 1.0.
6. **MAPE sensitivity to small actuals.** `models/evaluate.py` adds
