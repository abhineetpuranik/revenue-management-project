## 4. Optional Item Assessments

### Optional (a): Ground-truth revenue simulation
**Assessment: SAFE AND FEASIBLE.**
The demand formula lives in `data-pipeline/data_generation/sales.py`, function `generate_sales()`. However, for evaluation purposes we do not need the full function (which requires customer assignment). The formula for expected daily units per product is:
```python
lam = base_demand * combined_factor * festival_mult * (price / base_price) ** elasticity * promo_mult
```
This can be reconstructed directly in the evaluation script using the product's `base_demand`, `base_price`, `true_elasticity` from `gt_product_elasticity`, and a neutral factor (1.0 for combined_factor, 1.0 for promo at recommended price, 1.0 for festival). A simpler weekly-level version:
```python
expected_weekly_units(price) = baseline_demand * (price / current_price) ** true_elasticity
```
This is safe to import and use read-only. **Include in plan; mark Optional in evaluation script.**

### Optional (b): Multi-seed stability run (full pipeline)
**Assessment: SKIP.**
`run_pipeline.py` generates transactional tables that take "~2 min" and then features, training, elasticity, segmentation, pricing, explanations. Total estimated time is 10-15 minutes based on stage descriptions in `run_pipeline.py` (generate_transactional alone is ~2 min; training adds another 3-5 min). This exceeds the ~10 min threshold.
**Decision: do not run a full pipeline re-fit. The segmentation stability check (item 2d) runs K-Means only on already-computed RFM data with different seeds — that is fast and is REQUIRED, not optional.**
